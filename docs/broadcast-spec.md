# dona快V · 战术播报 v0.1

## 需求
将原版运行日志中的当前请求事件压缩成手机酒馆内的轻量悬浮播报。不是第二个控制台，不显示完整日志，不新增重试、认证、转发行为。管理面板名称为「快速 V 0.6.5 · dona美化」，脚本为「dona快V · 战术播报」。

## 事件映射
| 原始事件 | 悬浮窗 | 数据 |
|---|---|---|
| 首包等待 | 正在等待模型响应 | 模型（若已知）、实际等待时长 |
| 自动重试 | 请求受限 / 连接中断 / 上游异常 | HTTP 状态、当前重试次数/上限、真实剩余秒数（若存在） |
| 重试结束并再次请求 | 正在重新连接 | 模型、实际状态，不声称已经恢复 |
| 确认流式输出开始 | 通讯已建立 · 正在生成 | 模型 |
| 成功结束且有使用量 | 生成完毕 / 作战结算 | 输入、思考与生成、总 Token、成功传输耗时；若有独立思考/正文统计则可分开显示 |
| 失败/用户取消 | 请求失败 / 已取消 | 脱敏错误类别；取消不重试 |

截图例：429、2/4、等待5秒；502、3/4、等待5秒；连接建立后流式输出；结束时提示词72019、思考与生成10936、总82955、成功传输143.1秒。最后一项并非含所有重试的端到端总耗时。仅为示例，不写成生产固定数值。

## 数据源（静态检查）
Quick V 0.6.5 的 extension/failure-notice.js 与 failure-client.js 已提供重试状态；plugin/lib/failure-status.cjs 验证 phase、attempts、retry_remaining_ms。phase 枚举 unknown/running/retry_wait/finished/failed/cancelled；running 不等于已收到首包。extension/wait.js 有等待状态。
内嵌 app/api_helpers.py 的成功日志区分输入、思考、正文、总计，并另有流式完成耗时；app/logger.py 有累积统计；app/main.py 有 /api/stats 与 /stream-logs。累积值不能当本轮统计；原失败状态目前未证明提供本轮 token 结算。不可将整个日志流暴露给美化脚本。

## 最小适配契约
现已在原有受保护 failure-status 接口附加 `dona` 脱敏数字字段，并由原扩展发布同源 DOM 事件。只包含本轮不透明标识、事件类型、允许的错误类别/HTTP 状态、重试次数/上限、剩余时间、已知用量/耗时。事件与真实请求绑定，去重；跨请求不得串台；不返回提示词正文、项目 ID、密钥片段、Cookie、URL、设备标识或完整错误堆栈。接口权限沿用原机制，不改业务重试、限流或认证。数据缺失时省略，不从全局累计猜测，不编造统计。

## 0.1.0 集成实现

链路：服务商原始计数/原版进度与请求预算 → 原 FailureRound 的内存数字字段 → `/v1/chat/failure-status?trace=…` → 原插件 `/api/plugins/quick-v/failure-status?trace=…` → 原扩展既有轮询 → `dona-qv:status` → 独立播报。没有新增路由、凭据交换、日志订阅或网络轮询。原版认证、同源/回环检查、CSRF、请求跟踪及失败操作按钮保留。

服务端新增模块 `integration/dona_status.py`；构建精确插入原版 FailureRound、RequestBudget/PVP、Express/Cookie 原始用量与首个真实内容采集点。只观察，不修改请求参数、响应、异常传播、重试和续传。新增字段使用原请求绑定；原版已存在的容量（256）、活动 TTL（1200 秒）和终态 TTL（300 秒）继续适用，过期查询返回 unknown。原版 FailureRound 的容量/过期实现未修改，因此极长请求或被容量淘汰的请求可能丢失播报统计，不从其他请求补值。

`dona` 字段均可缺失：

| 字段 | 语义 |
|---|---|
| version | 1 |
| attempt / maxAttempts | 全局已开始尝试数 / 当前预算上限，含首次；某些 Cookie 兼容回退单独计数，超过预算时 UI 省略分母 |
| retryCount / retryMax | 普通请求预算中已开始的额外尝试 / 额外尝试上限；PVP 不设置这组字段 |
| streaming | 原版已确认第一个真实内容/思考/工具/图像块；running 或保活帧不等于 streaming |
| inputTokens | 服务商原始提示词计数 |
| thinkingTokens / outputTokens | 服务商明确返回的独立思考、候选正文计数 |
| thinkingAndOutputTokens | 仅在独立思考和正文字段均已知时相加 |
| totalTokens | 服务商原始 total 计数；不以全局累计差值或字符估算代替 |
| transferSeconds | 原版成功尝试的 gen_time：真流式为首个模型内容到成功结束，整包/假流式为成功整包调用耗时；不包含失败尝试和重试等待，也不承诺等于端到端用时 |

用量在新尝试前清空，只在 finished 终态返回；失败/主动取消不返回成功结算。独立 Token 字段缺失时省略，未知思考数不当作零。因保留原业务统计逻辑，原控制台可能展示经过上游调和/估算的数值；播报仅展示原始提供方数值，二者不保证每项完全相等。

事件名称 `dona-qv:status`；detail 为 `version:1, runId, seq, type` 加允许字段。type 为 start/waiting/retry/connecting/streaming/complete/failed/cancelled/reset；reset 用于切换聊天/连接及清理旧请求。终态去重、乱序和跨轮事件丢弃。酒馆助手脚本重载可通过 `dona-qv:subscribe` 读取桥内最后一份脱敏事件，过期终态不重播。事件只是同源展示消息，不是权限边界；安全边界在既有已认证接口，任何页面脚本本就拥有该页面权限。

本轮模型字段暂不从自定义模型路径传递，避免项目标识泄漏。原版接口不可用时不声称请求失败；若继续使用未适配原版，可降级观察旧提示 DOM，其计时是本轮生成用时，不能声称首字延迟。状态采样遵循原版 750ms 轮询；短于采样间隔的中间态可能不显示，不额外加密轮询。倒计时在本地按剩余毫秒递减，每秒更新一次，页面隐藏时暂停计时器，恢复按单调时钟校正；到零也不提前宣称已重新连接。

## 视觉与生命周期
小型战术终端，黑灰白、黄色等待、红色最终失败、绿色成功；同一个浮窗原地更新，不堆叠。默认避开输入框和停止按钮，提供关闭；正常等待/重试保持显示，完成短暂展示后自动收起（默认 8 秒，待真机验收）。最终失败可关闭但原版必要操作继续可用。空闲隐藏。尊重减少动效设置，不增加高频轮询；卸载彻底清理 DOM、监听与计时器。

## 验收
mock 重放截图流程、普通无重试成功、无 usage、取消、并发、断流、重复事件；核对计数与耗时语义，确认无敏感数据泄漏。真机验证酒馆助手宿主文档、页面生命周期与触控布局。
