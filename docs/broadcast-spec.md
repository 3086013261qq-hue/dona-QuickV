# dona快V · 战术播报 v0.1

## 需求
将原版运行日志中的当前请求事件压缩成手机酒馆内的轻量悬浮播报。不是第二个控制台，不显示完整日志，不新增重试、认证、转发行为。管理面板名称为「快速 V 0.6.5 · dona美化」，脚本为「dona快V · 战术播报」。

## 事件映射
| 原始事件 | 悬浮窗 | 数据 |
|---|---|---|
| 首包等待 | 正在等待模型响应 | 模型（若已知）、实际等待时长 |
| 自动重试 | 请求受限 / 连接中断 / 上游异常 | HTTP 状态、当前重试次数/上限、真实剩余秒数（若存在） |
| 重试结束并再次请求 | 正在重新连接 | 模型、实际状态，不声称已经恢复 |
| 确认流式输出开始 | 通讯已建立 · 正在生成 | 模型 |
| 成功结束且有使用量 | 生成完毕 / 作战结算 | 输入、思考与生成、总 Token、成功传输耗时；若有独立思考/正文统计则可分开显示 |
| 失败/用户取消 | 请求失败 / 已取消 | 脱敏错误类别；取消不重试 |

截图例：429、2/4、等待5秒；502、3/4、等待5秒；连接建立后流式输出；结束时提示词72019、思考与生成10936、总82955、成功传输143.1秒。最后一项并非含所有重试的端到端总耗时。仅为示例，不写成生产固定数值。

## 数据源（静态检查）
Quick V 0.6.5 的 extension/failure-notice.js 与 failure-client.js 已提供重试状态；plugin/lib/failure-status.cjs 验证 phase、attempts、retry_remaining_ms。phase 枚举 unknown/running/retry_wait/finished/failed/cancelled；running 不等于已收到首包。extension/wait.js 有等待状态。
内嵌 app/api_helpers.py 的成功日志区分输入、思考、正文、总计，并另有流式完成耗时；app/logger.py 有累积统计；app/main.py 有 /api/stats 与 /stream-logs。累积值不能当本轮统计；原失败状态目前未证明提供本轮 token 结算。不可将整个日志流暴露给美化脚本。

## 最小适配契约
若现有安全、同源接口未提供本轮统计，则增设仅供授权本地前端读取的脱敏事件接口或由原扩展发布受控事件。只包含本轮不透明标识、事件类型、允许的错误类别/HTTP 状态、重试次数/上限、剩余时间、模型、已知用量/耗时。事件与真实请求绑定，去重；跨请求不得串台；不返回提示词正文、项目 ID、密钥片段、Cookie、URL、设备标识或完整错误堆栈。接口权限沿用原机制，不改业务重试、限流或认证。数据缺失时省略，不从全局累计猜测，不编造统计。接口尚未实现。

## 视觉与生命周期
小型战术终端，黑灰白、黄色等待、红色最终失败、绿色成功；同一个浮窗原地更新，不堆叠。默认避开输入框和停止按钮，提供关闭；正常等待/重试保持显示，完成短暂展示后自动收起（默认 8 秒，待真机验收）。最终失败可关闭但原版必要操作继续可用。空闲隐藏。尊重减少动效设置，不增加高频轮询；卸载彻底清理 DOM、监听与计时器。

## 验收
mock 重放截图流程、普通无重试成功、无 usage、取消、并发、断流、重复事件；核对计数与耗时语义，确认无敏感数据泄漏。真机验证酒馆助手宿主文档、页面生命周期与触控布局。
